# 009 — MissionItem deadline 표시 포맷 수정

## 받은 티켓 스펙 요약

- scope: `entities/mission/ui/**`
  (`tickets/009.md` 파일은 저장소에 없어 사용자가 채팅으로 직접 준 스펙을 티켓 스펙으로 취급함.
  참고로 이 follow-up 필요성은 티켓 007 작업 로그(`docs/agent-runs/007.md`)의 "스코프 관련 노트"에서
  이미 예고됐던 내용과 정확히 일치함 — `MissionItem.tsx`가 `mission.deadline`을 ISO 8601 문자열
  그대로 렌더링하고 있다는 지적.)
- 요구사항
  - `MissionItem`이 `deadline`(ISO 8601, 예: `"2026-09-17T09:00:00+00:00"`)을 화면에 그대로 찍어서
    깨진 문자열로 보임
  - deadline이 있으면 "HH:mm 마감" 형태로 포맷, 단 오늘이 아니면 날짜도 함께 표시(예: "9/17 09:00 마감")
  - deadline이 없으면(007에서 선택 입력이 됨) 마감 표시 자체를 렌더링하지 않음
  - `entities/mission/model/`에 재사용 가능한 포맷 유틸이 있는지 먼저 확인 후 재사용
- DoD
  - [x] 오늘 마감인 미션은 "HH:mm 마감" 형태로 표시됨
  - [x] 오늘이 아닌 날짜 마감은 날짜+시각이 함께 표시됨
  - [x] deadline 없는 미션은 마감 관련 텍스트가 안 보임
  - [x] 기존 스타일(색상, 마감 초과 시 빨간색 표시 등)은 유지됨

## 사전 조사

- `entities/mission/model/`(`types.ts`, `mapMissionRow.ts`, `useMissions.ts`)을 확인했지만 deadline
  포맷팅 유틸은 없었음 — `mapMissionRow.ts`는 `null → ""` 코얼레싱만 하고 실제 표시 포맷 변환은
  하지 않음. 재사용할 기존 유틸이 없어 새로 작성함(scope가 `entities/mission/ui/**`이라 `model/`에
  새 파일을 추가하는 대신 `ui/` 안에 배치).
- `MissionItem.tsx`를 확인한 결과, "마감 초과 시 빨간색 표시" 같은 로직은 현재 코드에 존재하지 않음
  (중요 미션의 빨간 왼쪽 테두리/뱃지 스타일만 있음). DoD의 해당 항목은 "기존 스타일을 깨지 말 것"이라는
  의미로 해석해 별도 오버듀 강조 기능은 추가하지 않고, 기존 `border-l-red-shadow`/`Badge` 스타일을
  그대로 유지함.
- `features/add-mission/model/toDeadlineIso.ts`를 참고해 deadline이 브라우저 로컬 타임존 기준으로
  생성됨을 확인(`new Date(now.getFullYear(), ...).toISOString()`) — 표시 포맷도 `Date` 객체의
  로컬 getter(`getHours`/`getDate` 등)를 그대로 사용해 대칭을 맞춤.

## 변경한 파일 목록

### 신규

- `src/entities/mission/ui/formatMissionDeadline.ts` — ISO 8601 `deadline` 문자열을 받아
  `"HH:mm 마감"` 또는(오늘이 아니면) `"M/D HH:mm 마감"`으로 변환하는 순수 함수. `deadline`이 빈
  문자열이면 `null`을 반환(마감 미표시). "오늘" 판정과 비교 기준 시각(`now`)을 테스트 가능하도록
  두 번째 인자로 받되 기본값은 `new Date()`.
- `src/entities/mission/ui/formatMissionDeadline.test.ts` — 단위 테스트 4개
  (빈 문자열 → null / 오늘 마감 → "HH:mm 마감" / 오늘 아닌 마감 → "M/D HH:mm 마감" / 분 한 자리
  패딩 확인).

### 수정

- `src/entities/mission/ui/MissionItem.tsx` — `formatMissionDeadline(deadline)` 결과를
  `deadlineText`로 계산해서, 기존에 무조건 `{topic} · {deadline} 마감`으로 렌더링하던 부분을
  `{topic}{deadlineText ? \` · ${deadlineText}\` : ""}{actualFocusMinutes ? ... : ""}`로 변경.
  `actualFocusMinutes`가 이미 같은 방식(값 있을 때만 ` · N분` 추가)으로 조건부 렌더링되고 있던 걸
  그대로 따라감. 그 외 스타일(className, 뱃지, 완료/중요 표시 등)은 손대지 않음.

## DoD 체크 결과

1. **오늘 마감 → "HH:mm 마감"** — `formatMissionDeadline.test.ts`의 "오늘 마감이면..." 케이스에서
   `now`를 고정하고 같은 날짜의 deadline을 넣어 `"09:00 마감"`이 나오는 것을 확인.
2. **오늘 아닌 마감 → 날짜+시각 함께 표시** — 같은 파일의 "오늘이 아닌 마감이면..." 케이스에서
   `now`보다 하루 뒤인 deadline을 넣어 `"9/18 09:00 마감"`이 나오는 것을 확인.
3. **deadline 없으면 마감 텍스트 미표시** — `formatMissionDeadline("")`이 `null`을 반환하는 것을
   테스트로 확인했고, `MissionItem.tsx`에서 `deadlineText`가 `null`/falsy면 ` · ...` 세그먼트 자체를
   문자열에 넣지 않으므로 렌더링되지 않음(별도 컴포넌트 렌더 테스트 인프라—`@testing-library/react`
   등—가 이 프로젝트에 없어 로직 레벨로 검증함, 007 작업 로그와 동일한 제약).
4. **기존 스타일 유지** — `MissionItem.tsx`의 className/구조는 deadline 텍스트 조립 부분 외에는
   전혀 수정하지 않음. "마감 초과 시 빨간색" 기능은 원래 코드에 없었던 것으로 확인됐고, 이번 티켓
   스펙에도 새로 추가하라는 요구가 없어 손대지 않음(사전 조사 섹션 참고).

## 통합 게이트(npm run typecheck && npm run lint && npm run test) 실행 결과

- **`npm run typecheck`**(`next typegen && tsc --noEmit`) → 통과.
- **`npm run lint`**(eslint) → 에러/경고 없음.
- **`npm run test`**(`vitest run`) → 최초 실행 시 9개 테스트 파일 전부
  `TypeError: Cannot read properties of undefined (reading 'config')`로 실패했는데, 내가 추가한
  `formatMissionDeadline.test.ts`뿐 아니라 이번 세션에서 전혀 건드리지 않은 기존 테스트
  (`buildNagPrompt.test.ts`, `nagHistory.test.ts` 등)까지 전부 같은 에러로 실패해서 내 변경 때문이
  아니라 워크트리에 쌓인 `node_modules/.vite` vitest 캐시가 stale해진 환경 문제로 판단함.
  `rm -rf node_modules/.vite` 후 재실행하니 9 files / 39 tests 전부 통과(기존 35개 + 신규 4개).
  이후 통합 게이트 전체를 다시 순서대로(`typecheck && lint && test`) 재실행해도 동일하게 전부 통과함.
