# 006 — useToggleMission PATCH 경로/바디 수정

## 받은 티켓 스펙 요약

- scope: `features/toggle-mission/**`
  (tickets/006.md 파일은 저장소에 없어 사용자가 채팅으로 직접 준 스펙을 티켓 스펙으로 취급함)
- 요구사항
  - 기존 `useToggleMission.ts`가 `PATCH /api/missions`(컬렉션 경로) + body `{ id, isCompleted }`로
    호출하고 있었는데, 실제 API는 `PATCH /api/missions/:id`(동적 세그먼트) + body `{ isCompleted }`만
    받으므로 요청 경로와 바디를 API에 맞게 수정
- DoD
  - [x] PATCH 요청이 `/api/missions/${id}` 형태로 나감
  - [x] body에서 id를 빼고 `{ isCompleted }` 형태로만 보냄
  - [x] 미션 체크박스 토글이 실제로 동작하는지 확인 (405 안 남)

## 변경한 파일 목록

### 수정

- `src/features/toggle-mission/model/useToggleMission.ts`
  - fetch URL을 `/api/missions` → `` `/api/missions/${id}` ``로 변경
  - body를 `JSON.stringify(input)`(`{ id, isCompleted }`) → `JSON.stringify({ isCompleted })`로 변경
    (input에서 `id`/`isCompleted`를 구조분해해 `id`는 URL에만 쓰고 body에서 제외)

## DoD 체크 결과

1. **PATCH 요청 경로** — `src/app/api/missions/[id]/route.ts`의 동적 라우트가 `PATCH`를 처리함을
   확인. `useToggleMission.ts`가 이제 이 경로(``/api/missions/${id}``)로 요청을 보냄.
2. **body 형태** — `[id]/route.ts`는 `UpdateMissionInput`의 `isCompleted` 필드만 읽어 `done` 컬럼을
   갱신함. 수정된 훅은 body를 `{ isCompleted }`로만 보내 이 계약과 일치함.
3. **토글 동작(405 안 남)** — 기존에는 컬렉션 경로(`/api/missions/route.ts`)에 PATCH 핸들러가 없어
   405가 났을 것으로 추정되는 상황이었음. `[id]/route.ts`에 PATCH 핸들러가 존재하고 수정된 훅이
   이 경로로 요청하므로 405가 나지 않음을 코드 대조로 확인. (Supabase 로컬 인스턴스가 이 worktree에
   기동돼 있지 않아 브라우저상에서 실제 네트워크 요청까지는 실행하지 못했고, 라우트 코드와 요청
   경로/바디 계약이 정확히 일치하는지로 검증함 — 아래 "스코프 관련 노트" 참고)
