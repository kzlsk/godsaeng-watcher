## DoD 체크 결과

1. **페르소나별 시스템 프롬프트 분리** — `prompts/personas/{realist,furious-boss,clingy-friend}.md` 3개 파일로
   분리, `promptLibrary.ts`가 로드. `buildNagPrompt.test.ts`의 첫 테스트로 실제 파일 내용이 system 프롬프트에
   들어가는지 검증.
2. **강도 스케일링** — `prompts/intensity-scale.md`에 0-20/21-40/41-60/61-80/81-100 5구간 + 절대 금지 규칙 정의.
   `intensity=30`과 `intensity=90`으로 `buildNagPrompt` 호출 시 system 프롬프트가 서로 다름을
   `buildNagPrompt.test.ts`에서 직접 비교 검증(문자열이 다르고, 각각 "절제한다" / "최대치로 드러낸다" 지시문을 포함).
3. **재생성 시 반복 방지** — `nagHistory.ts`가 `(mode, personaId)` 키로 최근 5개 문구를 인메모리에 보관.
   `callOpenAI.ts`는 (a) 프롬프트에 "반복 금지" 섹션으로 최근 문구를 넘겨 LLM이 피하게 하고, (b) LLM 응답이
   최근 문구와 같으면 폴백으로 전환, (c) 폴백 선택도 `excludeQuotes`로 직전 문구를 회피. 동일 입력으로 연속
   호출했을 때 문구가 달라짐을 `callOpenAI.test.ts`에서 검증(모킹된 OpenAI 응답이 고정 문구를 반환해도
   두 번째 호출은 다른 값을 반환).
4. **API 실패/타임아웃 폴백** — 키 없음 / fetch reject / non-2xx 응답 각각에 대해 폴백 메시지로 전환되는 것을
   `callOpenAI.test.ts`에서 검증. 타임아웃은 `AbortController` + 8초 제한으로 구현(실제 8초 대기 테스트는
   비용 대비 낮은 가치라 생략, reject/non-2xx 경로로 동일 catch 블록이 타는 것을 확인했음).
5. **부적절한 출력 없음** — intensity-scale.md에 강도 무관 절대 금지 규칙(욕설/인신공격/혐오/자해 조장/협박 금지)을
   명시하고 모든 강도에서 이 텍스트가 system 프롬프트에 포함되는지 테스트. 폴백 문구 4×3×2=24개 전체에 대해
   공격적 표현 정규식 검사 테스트 추가.

## 통합 게이트(npm run typecheck && npm run lint && npm run test) 실행 결과

최초 구현 시점엔 `package.json`에 `typecheck`/`test` 스크립트가 없고 테스트 러너도 없어서
(이 worktree는 `node_modules`도 처음부터 없었고, `npm install`로 기존 lockfile 그대로 설치만 했었음)
`node --test`를 임시로 썼는데, 이후 사용자가 직접 `package.json`에 vitest를 설치하고
`"typecheck": "next typegen && tsc --noEmit"`, `"test": "vitest run"` 스크립트를 추가해서
테스트 파일을 vitest 문법으로 전환하고 위 스크립트들을 그대로 실행함.

- **`npm run typecheck`** (`next typegen && tsc --noEmit`) → 통과. `next typegen`이 라우트 타입을
  생성해주니 이전에 봤던 `src/app/(dashboard)/layout.tsx` / `src/app/layout.tsx`의 `LayoutProps` 에러도
  같이 없어짐(순수 `tsc --noEmit`만 돌렸을 땐 이 라우트 타입이 없어서 나던 에러였음, 이번 작업과는 무관).
- **`npm run lint`** (eslint) → 에러/경고 없음.
- **`npm run test`** (`vitest run`) → 20/20 통과.
  주의: vitest는 `tsconfig.json`의 `@/*` path alias를 기본으로는 못 읽어서(Vite가 별도 플러그인 없이는
  tsconfig paths를 안 봄), 루트에 `vitest.config.mts`를 추가해 `resolve.alias`로 직접 매핑함. 이 파일이
  없으면 `@/`로 시작하는 import가 있는 파일(사실상 이 프로젝트 거의 전부)의 테스트가 전부 실패함.

## 스코프 관련 노트 (블로커는 아니지만 후속 작업 필요)

- `src/app/api/nag/route.ts`, `src/entities/nag/**`, `src/shared/lib/demo-store.ts`, `src/shared/config/personas.ts`는
  전부 scope 밖이라 손대지 않음. 그 결과:
  - `generateNagMessage`는 intensity/deadlineOverCount/focusMinutesToday/focusMinutesWeek/currentStreak를
    선택 필드로 지원하지만, 현재 `route.ts`는 이 필드들을 채워 넘기지 않음 (nag_settings 자체가 아직 어디에도
    저장되지 않음 — demo-store에 없고 Supabase 스키마에도 없음). 하네스는 준비돼 있으니, `route.ts`가 이
    값들을 채워 넘기도록 수정하는 티켓이 별도로 필요함.
  - `callClaude.ts`라는 파일명이 이제 실제로는 OpenAI를 호출하는 `callOpenAI.ts`의 재노출 shim이 됨.
    `route.ts`의 import 경로(`@/shared/lib/ai/callClaude`)를 바꾸는 것도 scope 밖이라, 그 티켓에서 함께
    `@/shared/lib/ai/callOpenAI`로 import 경로를 정리하고 이 shim 파일은 삭제하는 걸 권장.
  - `@anthropic-ai/sdk` 의존성은 이제 아무 데서도 안 쓰지만 `package.json` 정리도 scope 밖이라 그대로 둠.
- `OPENAI_API_KEY` / `OPENAI_MODEL`(기본값 `gpt-4o-mini`) 환경 변수가 필요. `.env` 관련 파일도 scope 밖이라
  건드리지 않음 — 배포/로컬 환경에 값 설정 필요.
- `package.json`(vitest 설치, `typecheck`/`test` 스크립트)은 scope 밖이라 처음엔 blocker로 기록하고
  사용자에게 진행 방식을 물어봤고, 사용자가 본인 쪽에서 직접 `package.json`을 수정한 뒤 "테스트 파일만
  vitest로 바꿔서 진행"해달라고 확인해줌. 그 흐름에서 테스트를 실제로 돌리는 데 필요했던
  루트 `vitest.config.mts`(alias 매핑)는 같은 맥락의 후속 작업으로 판단해 추가함.
