# 016 — 쓴소리 문구 문장 구조 다양화

## 받은 티켓 스펙 요약

- scope: `shared/lib/ai/**`, `prompts/**`
  (tickets/016.md 파일은 저장소에 없어 사용자가 채팅으로 준 스펙을 티켓 스펙으로 취급함.
  `shared/lib/ai/**`는 실제 경로 `src/shared/lib/ai/**`로 해석함)
- 문제: 쓴소리 문구가 매번 비슷한 구조("완료율 → 집중시간 → 서운함 → 요청")로 반복됨
- 요구사항
  1. 요청마다 완료율/집중시간/스트릭/마감초과 중 1~2개를 서버에서 무작위로 골라 "이번엔 이걸 중심으로" 힌트 추가
  2. 각 페르소나 파일(prompts/personas/*.md)에 "매번 다른 문장 구조로 말하라" 다양성 지시 추가
  3. 완전히 같은 입력으로 여러 번 재생성해도 문장 구조가 달라지는지 테스트로 확인

## 원인 분석

- `buildNagPrompt.ts`의 user 프롬프트가 항상 같은 순서로 고정돼 있었음:
  `완료율 → 마감 초과 건수 → 누적 지연 → 오늘 집중 → 주간 집중 → 스트릭 → 남은 미션 → "한 문장으로 던져줘"`
- system 프롬프트에도 "무엇에 초점을 둘지", "어떤 문장 구조로 쓸지"에 대한 지시가 없고,
  "실제 숫자(완료 개수, 지연 시간 등)를 근거로"라는 문구가 완료율을 먼저 언급하는 쪽으로 유도했음.
- 입력이 같으면 프롬프트가 글자 단위로 완전히 같았기 때문에, 모델이 나열 순서를 그대로 문장 틀로 삼음.
  (반복 금지 힌트는 이전 문구 "표현"만 피하게 할 뿐, 틀 자체는 바꾸지 못했음)

## 변경 내용

- 요청마다 서버에서 무작위로 정하는 값 3가지 (`nagVariety.ts`)
  - **초점 요소 1~2개**: 완료율 / 집중시간 / 스트릭 / 마감초과 중 선택. 데이터가 없거나 말이 안 되는 요소는
    후보에서 제외함(집중시간·스트릭 값이 없을 때, 성공 모드이거나 마감초과 0건일 때의 마감초과). 없는 숫자를 모델이
    지어내지 않게 하기 위함. 모드별 동사도 다름(fail: 지적해줘 / success: 칭찬해줘).
  - **문장 구조 힌트 1개** (8종): 감탄사로 시작 / 질문으로 끝 / 아주 짧은 한 문장 / 숫자로 시작 / 비유 /
    행동 먼저·이유 나중 / 혼잣말 / 담담하다가 끝에서 폭발
  - **데이터 나열 순서**: 초점 요소를 맨 앞에 두고 나머지는 섞음. 마지막 "한 문장으로 던져줘" 지시는 그대로 유지.
- system 프롬프트에 `## 이번 요청의 방향 (매번 달라짐)` 섹션 추가. "데이터를 순서대로 훑지 마" 지시와
  "구조 힌트가 페르소나 말투 규칙과 충돌하면 말투 규칙이 우선"(예: realist의 감탄사 금지) 규칙도 함께 넣음.
- 각 페르소나 파일에 `## 문장 구조 다양성` 섹션 추가. 페르소나 말투에 맞는 예시를 넣고, clingy-friend에는
  "완료율 → 집중시간 → 서운함 → 부탁" 고정 틀 금지와 "부탁으로 끝내지 않아도 된다"를 명시함.
- `buildNagPrompt`가 `options.random`(테스트용 시드 난수 주입)을 받고, 반환값에 `variety`를 추가로 담음.
  기존 호출부(`callOpenAI.ts`)는 `{ system, user }`만 구조분해하므로 변경 없음.

## 작업 중 겪은 문제

1. **스크립트로 파일을 고치다가 `"\n"`이 실제 줄바꿈으로 들어감**: Python 치환 스크립트에서 `join("\n")` 두 곳이
   문자열 리터럴 안에 진짜 줄바꿈으로 바뀌어 문법이 깨짐. diff를 보고 바로 발견해 다시 치환함 (게이트 실행 전에 수정)
2. **테스트 정규식 실수**: `^`로 시작하는 패턴을 여러 줄짜리 문자열 전체에 적용해 첫 줄만 검사되는 문제. 실행 전에 발견해
   줄 단위 검사로 수정
3. **라이브 검증 스크립트 실행 실패 2회**: 로컬 `node_modules`에 tsx가 없었고, 전역 tsx는 CJS로 변환해서 top-level await를
   지원하지 않았음. 코드를 `async function main()`으로 감싸 해결. 임시 파일은 실행 후 삭제함
4. **realist 다양성 부족**: 5개 중 4개가 "마감을 두 건이나…"로 시작. 감탄사 금지·건조한 톤 규칙 때문에 일부 힌트가 무시됨
5. **티켓 파일·시나리오 디렉터리 없음**: `tickets/016.md`와 `scenarios/`가 없어서 채팅 스펙을 기준으로 삼고 라이브 검증으로 대체
6. **통계 테스트의 이론적 불안정성**: `Math.random`을 쓰는 테스트 3개(100회 첫 줄, 200회 선두 요소, 400회 힌트 커버리지,
   callOpenAI 5회)는 이론상 실패 확률이 0은 아님. 계산상 무시할 수준(예: 400회 뽑기에서 8종 중 하나가 안 나올 확률은 약 10^-22)이지만
   CI에서 간헐적으로 실패하면 시드 주입 방식으로 바꿀 것
7. **CRLF 경고**: git이 LF→CRLF 변환 경고를 냈지만 autocrlf 설정에 따른 정상 동작이라 diff 내용에는 영향 없음

## 실제 모델 출력 검증 (scenarios/ 대체)

AGENTS.md는 프롬프트를 바꾸면 `scenarios/`로 재검증하라고 하지만 저장소에 `scenarios/` 디렉터리가 없음.
그래서 같은 입력(fail, 1/4 완료, 마감초과 2건, 오늘 집중 15분, 스트릭 3일)으로 실제 `generateNagMessage`를
페르소나별 5회씩 호출해 확인함 (gpt-4o-mini, 임시 스크립트, 커밋 안 함).

- clingy-friend: "헐..." / "진짜..." / "오늘 미션도..." / "야아..."로 시작 방식이 나뉨. 초점도 스트릭·완료율·집중시간으로
  바뀌고, 5개 중 요청("~해줘")으로 끝나는 건 1개뿐 → 기존 "완료율→집중→서운함→요청" 고정 틀이 깨짐
- furious-boss: 느낌표 단정 / "야," 호통 시작 + 질문으로 끝맺음 / 스트릭 경고형 등으로 나뉨
- realist: 비유형("초라한 나비 한 마리가…")과 원인 진단형은 나왔지만, 5개 중 4개가 "마감을 두 건이나…"로 시작함.
  3가지 패턴 이상으로 나뉘긴 했으나 시작 방식의 다양성은 세 페르소나 중 가장 약함 (아래 "남은 이슈" 참고)

## 남은 이슈 / 참고

- realist는 "감탄사 금지·건조한 톤" 제약이 강해 구조 힌트 중 일부(감탄사 시작, 감정 폭발)가 말투 규칙에 밀려 무시됨
  (의도된 우선순위). 시작 방식이 "마감을 ~ 상황에서"로 쏠리면, realist 전용 구조 힌트 풀을 따로 두는 걸 후속 티켓으로 고려할 만함.
- `temperature`(0.9)와 모델 설정은 바꾸지 않음.
- 커밋하지 않고 변경사항을 워킹 트리에 그대로 둠 (AGENTS.md 브랜치 라이프사이클 규칙).
