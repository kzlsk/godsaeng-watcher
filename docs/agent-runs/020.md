(하네스·캡처 파일은 세션 임시 폴더에 있고 저장소에는 넣지 않았음)

2. **헤더 반응형 깨짐** — 헤더가 한 줄에 로고 + "연속 N일" + 테마 토글 + 로그아웃을 모두 넣고 있어

   폭을 훑어 보니 **모바일만의 문제가 아니었다**(아래 표).

3. **미션 추가 모달 버튼 잘림** — 375×667에서 마감 피커를 연 상태로 재현. 모달 폼에 높이 제한이

   제목이 화면 위로, 제출 버튼이 화면 아래로 빠져나갔다.

   오버레이가 스크롤되지 않아 **버튼에 접근할 방법이 아예 없었다**(= 모바일에서 미션 추가 불가).

## 작업 내용

### 1. 하단 네비게이션 — (A) 실제 동작 연결

`nav.ts`가 섹션 앵커 id를 정의하고(`NAV_SECTION_IDS`), `page.tsx`의 각 섹션 래퍼가 그 id를 달고,
`MobileTabBar`가 클릭 시 `getElementById` → `window.scrollTo({ behavior: "smooth" })` 한다.

- 오늘 → 대시보드 최상단
- 타이머 → `#section-timer` (FocusTimerPanel)
- 리포트 → `#section-streak` (StreakBar)
- 설정 → `#section-nag` (NagBanner · 잔소리 설정이 들어 있는 배너)

처음에는 스코프 제약 때문에 **섹션 제목 텍스트**("집중 타이머" 등)로 대상을 찾았는데, 문구가 바뀌면
조용히 동작을 멈추는 구조였다. 스코프 밖 변경을 허용받아 앵커 id 방식으로 교체했고, 덕분에
제목 텍스트 정규화/매칭 로직과 그 테스트가 통째로 없어졌다. 위젯이 로딩 중(스켈레톤)이어도
섹션 래퍼는 항상 그려지므로 그 동안에도 이동이 된다.

`id`는 섹션 래퍼(`<section>`)에만 달고 위젯 내부는 건드리지 않았다. 위젯들의 루트가 `w-full`이라
래퍼가 끼어도 레이아웃은 그대로다(`MissionBoard`는 grid 자식, 나머지는 flex 자식).

### 2. 헤더 반응형

한 줄 배치는 **lg(1024px) 이상**에서만 쓰고, 그 아래는 두 줄로 쌓는다.

로고 워드마크("갓생 감시자") 높이로 줄바꿈 여부를 측정한 값:

| 폭 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 375px | 2줄(45px) 깨짐 | 1줄(23px) |
| 390px | 1줄 | 1줄 |
| 640 / 700px | **2줄 깨짐 (원래부터 깨져 있던 구간)** | 1줄 |
| 768px | 1줄 (프로바이더 뱃지를 넣으면 깨짐) | 1줄 |
| 834 / 900 / 1024 / 1280px | 1줄 | 1줄 |

640~700px(태블릿/작은 창)는 **이번 티켓 이전부터 이미 깨져 있었고**, 프로바이더 뱃지를 넣자
깨지는 구간이 768px까지 넓어졌다. 원인이 같아 모바일만 고치지 않고 한 줄 배치 자체를 lg로 올렸다.
모든 폭에서 가로 넘침(`scrollWidth > clientWidth`)도 없다.

- 1행: 로고 + 날짜 (날짜는 기존에 모바일에서 숨겨져 있었는데, 1행에 자리가 남아 다시 보이게 함)
- 2행: `[프로바이더][닉네임][연속 N일]` ↔ `[테마 토글][로그아웃]` (`justify-between`)
- 두 줄/한 줄을 가르는 기준(lg)과, 뱃지·버튼을 작게 줄이는 기준(sm)은 분리했다.
  640~1023px에서는 두 줄이되 닉네임·로그아웃 라벨이 정상 크기로 다 보인다
- 2행 컨테이너에 `flex-wrap`을 둬서 최악의 경우에도 가로로 넘치지 않고 줄바꿈된다
- 모바일에서는 뱃지/버튼 패딩·글자를 한 단계 줄이고, 로그아웃은 **아이콘만** 남긴다
  (라벨은 `sm:inline`, 의미는 `aria-label`로 유지)
- 닉네임은 기존대로 모바일에서 숨긴다. "닉네임은 잘라내지 않고 전체 표시"라는 기존 결정(코드 주석)이
  있어 `truncate`를 쓸 수 없고, 긴 닉네임이 모바일 폭을 바로 넘기기 때문

### 3. 미션 추가 모달

- 폼: `max-h-[calc(100dvh-2rem)] overflow-hidden` (2rem = `Modal`의 `p-4` 상하 여백)
- 제목 줄: `shrink-0`
- 입력 영역: `min-h-0 flex-1 overflow-y-auto` → **이 영역만 스크롤**
- 취소/미션 추가 버튼: 스크롤 영역 밖으로 빼서 하단 고정(`shrink-0 border-t-2`)
- `DeadlineWheelPicker`: 휠 컬럼에 `overscroll-contain`을 줘서 휠을 끝까지 돌렸을 때 모달 본문이
  따라 스크롤되는 현상을 막고, 컬럼 폭을 `w-full` → `min-w-0 flex-1`로 바꿔 두 컬럼이 반씩 갖게 함.
  `scrollbar-none`은 Tailwind v4 기본 유틸(`scrollbar-width: none`)이 맞아 그대로 두고,
  이 속성을 모르는 사파리/구형 웹킷용으로 `[&::-webkit-scrollbar]:hidden`만 추가

### 4. 로그인 프로바이더 — 닉네임 왼쪽 브랜드 로고 뱃지

- 데이터: `useUser()`가 세션에서 프로바이더를 읽어 `AppUser.provider`로 내려주고,
  `page.tsx`가 헤더에 prop으로 넘긴다. 추출 규칙은 `resolveAuthProvider()` —
  `app_metadata.provider` → 없으면 `identities[].provider`
- 표시
  - 카카오: 노란 배경(`bg-yellow` = #FEE500) + 검정 말풍선 심볼
  - 구글: 흰 배경 + 공식 4색 G 로고
  - 크기는 옆 뱃지 높이에 맞춰 모바일 `size-7`(28px) / sm 이상 `size-9`(36px), 심볼은 16~18px
  - 브랜드 색이라 테마 토큰을 쓰지 않고 고정(023에서 로그인 버튼에 적용한 기준과 동일)
  - 닉네임은 모바일에서 숨지만 **이 로고 뱃지는 모든 폭에서 계속 보인다**
- 로고가 없는 프로바이더(이메일 등)는 `describeAuthProvider()`의 한국어 텍스트 뱃지로 폴백
  (`email`→이메일, 모르는 값은 원문 그대로, 값이 없으면 뱃지 자체를 그리지 않음)
- 로고만으로는 스크린리더에 의미가 전달되지 않아 `role="img"` + `aria-label`/`title`로
  "OO 계정으로 로그인했습니다."를 붙였다

### 5. 중복/구조 정리 (스코프 밖 승인분)

- **브랜드 심볼 공용화** — 카카오/구글 SVG가 로그인 버튼과 헤더 뱃지 두 곳에 필요해져
  `shared/ui/BrandSymbol.tsx`로 올리고 양쪽이 그걸 쓴다. 023 로그에 적힌
  "다른 곳에서도 쓰이면 그때 shared로 올리면 됨" 조건이 충족된 시점이라 판단.
  크기는 **기본값을 두지 않고 호출부가 지정**하게 했다 — `cn()`이 tailwind-merge가 아니라 단순
  join이라 기본 size 클래스와 호출부 size 클래스가 같이 남으면 승자가 불안정해지기 때문
  (023에서 border 두께로 같은 문제를 겪었음). 로그인 버튼의 `h-[18px] w-[18px]`은
  `size-4.5`(= 18px)로 바뀌었고, 렌더 결과가 18×18로 동일한 것을 확인함
- **프로바이더 조회 위치** — 헤더가 `supabase.auth.getUser()` + `onAuthStateChange`를 직접
  구독하고 있었는데(= `useUser`와 세션 구독이 두 벌), `useUser` 한 곳으로 모으고 헤더는 prop만 받는
  표현 컴포넌트로 되돌렸다. FSD상으로도 entities → widgets 방향이 자연스럽다

## 확인 필요 / 판단한 것

1. **"리포트 = 주간 통계"의 대상** — 전용 리포트 섹션이 없어서, 최근 7일 + 유지 현황을 보여주는
   `StreakBar`로 보냈다. `MissionBoard` 상단의 "주간 점수" 통계 줄이 더 맞다면
   `nav.ts`의 `report` 항목이 가리키는 앵커만 `NAV_SECTION_IDS.missions`로 바꾸면 된다.
2. **"설정 = 잔소리 설정"의 대상** — 독립된 설정 화면/섹션이 없다. 잔소리 설정(페르소나 탭 +
   강도 슬라이더)은 `NagBanner` 안에 있고 슬라이더는 페르소나 탭을 눌러야 열린다. 그래서 설정 탭은
   `NagBanner`까지 스크롤만 시킨다. 진짜 설정 화면이 필요하면 별도 티켓이 맞다.
3. **모달 하단 버튼 줄에 구분선(`border-t-2`)이 생겼다** — 본문이 스크롤되므로 경계가 보이는 게
   낫다고 판단해 넣었다. 데스크톱 디자인도 같이 바뀌므로, 원하지 않으면 그 클래스만 빼면 된다.
4. **다크모드 / 실제 기기 터치 동작**은 확인하지 못함(아래 한계 참고).
   로고 뱃지 배경(노랑/흰색)은 브랜드 색 고정이라 다크모드에서도 그대로다.

## 검증 방법과 결과

실제 로그인이 필요한 화면이라 dev 서버로는 대시보드를 띄울 수 없어 아래 방식으로 검증함.

1. `npm run build`로 CSS를 생성하고, 이번에 쓴 유틸이 **실제로 CSS 규칙으로 나오는지** 확인
   (tsc/eslint는 Tailwind 클래스 유효성을 검사하지 않음):
   `max-h-[calc(100dvh-2rem)]`, `overscroll-contain`, `[&::-webkit-scrollbar]:hidden`,
   `scrollbar-none`, `flex-wrap`, `size-4.5`(= 18px) 모두 생성 확인.
   (이 과정에서 `scrollbar-none`이 Tailwind v4 기본 유틸임을 확인해 임의 속성으로 바꿨던 걸 되돌림)
2. 컴포넌트의 클래스/마크업을 그대로 옮긴 정적 하네스 + 위 CSS를 헤드리스 Chrome으로 측정/캡처
   - **폭 훑기(375·390·640·700·768·834·900·1024·1280px)**: 수정 전 375/640/700px 깨짐
     → 수정 후 전 구간 1줄 유지, 가로 넘침 없음
   - **모달 375×667(마감 피커 연 상태)**: 수정 전 제출 버튼 `bottom=730`(뷰포트 667, 잘림)
     → 수정 후 `bottom=632`(항상 보임), 제목도 화면 안

## 고려한 방법과 선택 이유

### (3) 모바일 섹션 순서 — 핵심 결정

데스크톱은 **좌 [통계·미션] / 우 [타이머·스트릭]** 두 열이고, 모바일은
**통계 → 스트릭 → 타이머 → 미션**이라 단순 DOM 순서로는 둘을 동시에 만족할 수 없다.

| 방법 | 판단 |
| --- | --- |
| 같은 위젯을 모바일용/데스크톱용으로 두 번 렌더링 후 `sm:hidden` | **탈락**. 요구에서 명시적으로 금지했고, 쿼리 훅이 두 벌 붙고 같은 내용이 접근성 트리에 중복된다 |
| grid에 `col-start`/`row-start`로 4개를 직접 배치 | **탈락**. grid는 행 높이가 좌우로 묶인다. 지금 데스크톱은 두 열이 서로 독립적인 높이를 갖는 구조라, 행이 묶이는 순간 타이머 패널이 통계 높이만큼 늘어나거나 미션 시작 위치가 내려간다 → 데스크톱이 바뀐다 |
| 열 래퍼에 `display: contents` + `order` | **채택**. lg 미만에서는 두 열 래퍼가 박스를 만들지 않아 4개가 바깥 flex의 직접 자식이 되고 `order`로 순서를 잡을 수 있다. lg에서는 래퍼가 다시 `flex flex-col`이 되어 **기존 두 열 구조가 그대로** 남는다. DOM은 한 벌뿐이다 |

`display: contents`는 과거 일부 브라우저에서 접근성 트리에서 사라지는 버그가 있었지만, 여기서
contents가 되는 건 의미 없는 레이아웃용 `div` 두 개뿐이라(리스트/테이블 같은 시맨틱 요소가 아님)
영향이 없다. 스크롤 앵커로 쓰는 `<section id>`들은 contents가 아니라 정상적으로 박스를 만든다.

### (4) 통계 2x2 — `StatCell`을 못 고치는 제약 아래서

`shared/ui/StatCell.tsx`는 이번 스코프 밖이라 내부를 고칠 수 없었다. 넘길 수 있는 건
`className`과 `ReactNode`(value/caption)뿐이다.

- **구분선**: `StatCell`은 `sm:border-r-2 last:border-r-0`만 갖고 있어 모바일에는 선이 없다.
  2x2에서는 "1행 아래"와 "왼쪽 칸 오른쪽"에만 선이 필요하므로, 칸마다 필요한 테두리를
  `className`으로 넘겼다(1번 칸 `border-b-2 border-r-2 sm:border-b-0` 식).
  데스크톱은 컨테이너의 `sm:divide-x-2` + `StatCell`의 `sm:border-r-2` 조합이 그대로라 변화 없다.
- **캡션 잘림**: 2열이면 칸 폭이 ~169px이라 "이번 주 미룬 시간 0분"이 접힐 수 있었다.
  글자 크기를 줄이는 대신 **모바일 좌우 패딩을 줄이는 쪽**을 택했다(값/캡션 크기는 데스크톱과 동일 유지).
  이때 `className="px-3"`처럼 변형 없는 유틸을 주면 `StatCell`의 기본 `px-4.5`와 같은 속성이 겹쳐
  **누가 이기는지가 Tailwind 정렬 순서에 달려 불안정**하다(023에서 border 두께로 겪은 문제).
  그래서 `max-sm:px-3 max-sm:py-3.5`로 줬다. 미디어 변형은 항상 기본 유틸 뒤에 생성되므로 확실히 이긴다.
  빌드된 CSS에서 `@media not all and (min-width:40rem){.max-sm\:px-3{...}}`로 나오는 것을 확인했다.
  결과: 4개 캡션 모두 18px(= 1줄)로 측정됨.

### (2) 쓴소리 버튼 — 작게 + 우측 정렬

- **크기**: `Button`(shared/ui)은 023 소유라 손댈 수 없고 `size`는 반응형이 안 된다.
  그래서 **기본을 `size="sm"`으로 낮추고 `sm:` 변형으로 데스크톱 lg 크기(px-4.25/py-4.5/14.5px)를 복원**했다.
  (반대로 `size="lg"`에 모바일 축소 클래스를 얹는 방식은 위와 같은 "변형 없는 유틸끼리 충돌"이라 불안정)
  터치 높이는 `min-h-9`(36px)로 보장 — 실측 36px.
- **위치**: "인용문과 같은 줄 오른쪽"은 모바일 폭에서 인용문을 심하게 눌러 글자가 잘게 접힌다.
  그래서 **인용문 아래 우측 정렬**(`self-end`)을 택했다. 컨테이너는 `items-start`를 유지해서
  인용문 자체는 왼쪽 정렬 그대로다. 데스크톱은 `sm:self-auto`로 기존 같은 줄 배치로 돌아간다.
  버튼은 `whitespace-nowrap`이고 실측 폭 99px이라 인용문이 길어져도 가로로 넘치지 않는다
  (배너 오른쪽 안쪽 여백에 정확히 붙음: rightGap 19px = 패딩 16 + 테두리 3).

### (1) 페르소나 탭 — 2x2 선택

"한 줄에 4개"는 페르소나 이름이 가변(예: "집착하는 친구", "실망한 선배")이라 375px에서 글자를
줄이거나 잘라야 해서 탈락. **2열 그리드(2x2)** 를 택했고 `sm` 이상은 기존 한 줄 flex 그대로다.
칸이 같은 너비라 선택된 탭의 밑줄(`border-b-[3px]`)이 칸 전체 폭으로 그려진다 — 기존엔 글자 폭만큼이었다.
2x2에서는 이게 오히려 선택 상태가 또렷해 그대로 뒀다(동작/props는 건드리지 않음).

### (5)(6) 헤더 — 닉네임 노출 + 박스 규격 통일

- **프로바이더 뱃지를 닉네임 칩 안으로 흡수**했다. 박스가 하나 줄어 모바일 가로 공간이 생기고,
  원래 요구였던 "닉네임 옆에 로고"에도 더 맞는다. 로고는 브랜드 바탕색(노랑/흰색) 정사각형 위에 올린다
  (다크모드에서 검정 말풍선이 묻히지 않게). 로고가 없는 프로바이더(이메일 등)는 칩 안에 작은 텍스트로 표시.
- **규격**(코드에 `HEADER_BOX` / `HEADER_BOX_SQUARE` 상수로 고정):
  - 높이 36px — 고정 `h-9`가 아니라 `min-h-9`. 닉네임을 자르지 않는 게 요구라서, 아주 긴 닉네임이면
    칩 안에서 줄바꿈되고 칸이 늘어나야 하기 때문
  - 테두리 2px(색만 역할별로 다름: 표시=line / 스트릭=green-light / 조작=ink·line-strong)
  - 글자 12px, `font-bold`, 가로 패딩 12px(`px-3`), 아이콘 전용 칸은 정사각형(`w-9`)
  - `ThemeToggle`도 같은 36px이 되도록 크기 클래스만 맞췄다(`min-h-9` + `items-stretch`)
- **로고 줄바꿈 방지**: `Logo`에 `shrink-0 whitespace-nowrap`을 넘겼다(컴포넌트 수정 아님, 기존 className prop 사용).
- **날짜**: 모바일에서 11px로 한 단계만 줄이고 1행 오른쪽에 유지했다(1행은 로고+날짜뿐이라 자리가 남는다).
- 2행은 `flex-wrap`이라 닉네임이 길어지면 가로로 넘치는 대신 한 줄 더 내려간다.

### (7) 설정 탭 삭제

`MOBILE_NAV_ITEMS`에서 `settings` 항목을 빼고, 그 탭만 쓰던 앵커 `NAV_SECTION_IDS.nag`과
`page.tsx`의 해당 `<section>` 래퍼도 같이 지웠다. 쓰지 않게 된 `missions` 앵커도 함께 정리했다.
탭 버튼은 `flex-1`이라 3개가 자동으로 균등 분배되고, 활성 스타일은 인덱스가 아니라
`active === item.id`로 결정돼 마지막 탭도 정상이다(테스트로 탭 구성도 고정).

## 판단한 것

### 라벨만 바꾸지 않고 스크롤 대상도 같이 바꿨다

"리포트" 탭은 스트릭(최근 7일) 섹션을 가리키고 있었다. 라벨만 "미션"으로 바꾸면

- 통계 → `#section-stats`
- 타이머 → `#section-timer`
- 미션 → `#section-missions`

그 결과 스트릭 섹션은 더 이상 어떤 탭의 대상이 아니라서 앵커 id를 없앴다(순서 클래스만 남김).
탭 대상이 "페이지 최상단"인 경우가 사라져 `MobileNavTarget`의 `top` 종류도 함께 정리했다

> 참고: 이제 "통계"를 누르면 쓴소리 배너는 위로 지나가고 통계 패널이 화면 위에 붙는다.
> 최상단(쓴소리 배너부터)으로 가는 게 더 낫다면 `MOBILE_NAV_ITEMS`의 첫 항목만 바꾸면 된다.

### 활성 탭 판정 방식

**방법 비교**

| 방법 | 판단 |
| --- | --- |
| `IntersectionObserver`로 "화면에 보이는 섹션" 감지 | 섹션 높이가 제각각이라 여러 개가 동시에 걸치고, 어느 걸 고를지 결국 추가 규칙이 필요하다. 또 순수 함수로 떼기 어려워 테스트가 힘들다 |
| 스크롤 이벤트 + 각 섹션 top 비교 (채택) | 규칙이 한 줄로 설명된다. 좌표 계산만 떼어내면 **순수 함수**라 단위 테스트가 쉽다 |

채택한 규칙(`resolveActiveNavId`):

- 판정선 = `scrollY + NAV_ACTIVE_OFFSET`(20px). 이 선보다 **위에서 시작한 섹션 중 마지막** 것이 활성
- 첫 섹션보다 더 위에 있으면 **첫 번째 탭**(통계) — 쓴소리 배너를 보고 있을 때가 여기 해당한다.
  요구사항의 "위로 스크롤해 올라가면 통계" 가 이 규칙으로 처리된다
- 문서 끝에 닿으면 **마지막 탭**(미션). 마지막 섹션이 짧아 화면 위까지 못 올라오는 경우에도
  스크롤을 끝까지 내렸으면 그 섹션을 보고 있는 것이기 때문
- `NAV_ACTIVE_OFFSET`은 `NAV_SCROLL_MARGIN`(12px)보다 커야 한다. 탭을 눌러 스크롤이 끝나면
  그 섹션 top이 화면 위에서 딱 12px 아래에 있는데, 판정선이 그보다 위면 방금 누른 탭이
  활성으로 안 잡히기 때문이다. 이 관계도 테스트로 고정했다
- **DOM 순서가 아니라 실제 화면 좌표(top)로 정렬**한다. 모바일 순서는 CSS `order`로 만들어져서
  DOM 순서(통계 → 미션 → 타이머 → 스트릭)와 화면 순서(통계 → 스트릭 → 타이머 → 미션)가 다르다

**구현 세부**

- 스크롤 이벤트는 `passive`로 받고 `requestAnimationFrame`으로 묶어 프레임당 한 번만 계산한다
  (섹션 3개의 `getBoundingClientRect`만 읽는다)
- 같은 값으로 `setActive`를 불러도 React가 리렌더를 건너뛰므로 매 프레임 호출해도 괜찮다
- **탭을 눌러 부드럽게 스크롤하는 동안에는 감지를 0.7초 쉰다.** 안 그러면 지나가는 중간 섹션들이
  차례로 활성화되며 탭이 깜빡인다. 스크롤이 끝나면 어차피 누른 탭이 활성으로 잡힌다
- 처음에 `Date.now()`로 "언제까지 쉴지"를 쟀더니 `react-hooks/purity` 린트 규칙에 걸렸다
  (렌더 스코프에서 순수하지 않은 함수 호출 금지). 저장소에 이미 있는 패턴
  (`DeadlineWheelPicker`의 ref + `setTimeout` + 정리) 으로 바꿔 통과시켰다

처음엔 `truncate`만 풀어 줄바꿈되게 했는데, 측정해 보니 그것만으로는 부족했다.
**모바일에서 제목이 쓸 수 있는 폭이 120px(중요 뱃지가 있으면 83px)밖에 안 됐기 때문**이다.
체크박스 + 뱃지 + "집중 시작" 버튼 + 구분선 + 휴지통이 전부 제목과 같은 줄에 있어서다.

375px 실측(제목 줄 수):

| 제목 | 말줄임만 풀었을 때 | 버튼을 아랫줄로 내린 뒤 |
| --- | --- | --- |
| "코테 2문제" (6자) | 1줄 | 1줄 |
| 25자 | 3줄 | **2줄** |
| 39자 + 중요 뱃지 | 6줄 | **2줄** |
| 52자(긴 URL) | 2줄인데 가로로 삐져나감 | **2줄, 안 넘침** |

| 방법 | 판단 |
| --- | --- |
| `line-clamp-2`로 2줄까지만 | **탈락**. 폭이 120px이라 2줄이어도 17자까지밖에 안 보인다. "텍스트 안 가리게"라는 요구를 못 지킨다 |
| 제목 글자 크기 축소 | **탈락**. 목록의 주 정보를 작게 만드는 건 본말전도고, 폭 문제라 근본 해결이 안 된다 |
| 말줄임만 풀어 줄바꿈 | **부족**. 위 표처럼 25자가 3줄, 39자가 6줄이 된다 |
| 모바일에서 실행 버튼을 아랫줄로 내려 제목 폭 확보 (채택) | 제목 폭 120px → **263px**. 대부분 1~2줄로 들어가고, 글자를 하나도 가리지 않는다 |

- 줄바꿈은 `break-words`(= `overflow-wrap: break-word`)로 시작했는데, 긴 URL 한 줄이 여전히
  칸을 넘었다. **`wrap-anywhere`(= `overflow-wrap: anywhere`)로 교체**해서 해결했다.
  둘의 차이는 최소 너비 계산에 반영되느냐인데, flex 안에서는 anywhere라야 넘침이 확실히 막힌다.
  (Tailwind v4에 기본 유틸로 있는 것을 확인하고 씀 — 빌드 CSS에 `.wrap-anywhere{overflow-wrap:anywhere}` 생성 확인)
- 제목이 2줄이 되면 체크박스/뱃지가 세로 가운데에 떠 보여서, 모바일에서만 위쪽 정렬(`items-start`)로 바꿨다.
- **데스크톱(sm 이상)은 기존 그대로** 한 줄 `truncate` + 버튼 같은 줄이다(1280px 실측에서 전부 1줄 유지).
  데스크톱은 제목 폭이 720~763px이라 실제로 잘릴 일이 거의 없다.

## 검증

`MissionItem`의 마크업/클래스를 그대로 옮긴 하네스(실제 빌드 CSS)에 길이별 제목 4종을 넣고
375 / 390 / 1280px에서 측정했다. 제목은 `font-sans`(Inter)인데 한글은 어차피 시스템 한글 폰트로
폴백되므로, 이 측정에는 웹폰트 유무가 영향이 없다.

- 375px: 6자 1줄 / 25자 2줄 / 39자+뱃지 2줄 / 52자 URL 2줄 — **전부 잘림 없음**, 가로 스크롤 없음
- 390px: 25자는 1줄로 줄어듦, 나머지 동일
- 1280px: 네 가지 모두 1줄 + 기존 말줄임 유지 (데스크톱 변화 없음)
- 스크린샷으로도 확인: 제목이 2줄로 다 보이고, 실행 버튼은 아랫줄 오른쪽에 정렬됨

### 미검증 / 사람이 확인할 것

- 실제 데이터(진짜 미션 제목들)로는 못 봤다. 한 줄에 다 안 들어가는 아주 긴 제목이 여러 개면
  목록이 길어진다 — 지금은 "글자를 가리지 않는다"를 우선했다.
  만약 목록이 너무 길어져 보기 불편하면 `line-clamp-3` 정도로 상한을 두는 선택지가 있다(현재는 상한 없음)
- 버튼이 아랫줄로 내려가면서 **미션 한 줄의 높이가 모바일에서 늘어난다**(짧은 제목 기준 약 40px).
  대신 제목이 잘리지 않는다 — 이 교환이 괜찮은지는 실기기에서 봐 주면 좋겠다
- 터치로 "집중 시작"/삭제를 누를 때의 오터치 여부(버튼 사이 구분선·간격은 기존 그대로 유지했다)
