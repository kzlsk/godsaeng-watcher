# 013 — 미션 추가 모달 deadline 입력을 시/분 휠 피커로 전환

## 받은 티켓 스펙 요약

- scope: `features/add-mission/ui/**`
- `tickets/013.md` 파일은 저장소에 존재하지 않아, 사용자가 대화에서 직접 준 스펙을
  티켓 스펙으로 취급함(브랜치명 `ticket/013-deadline-input-ux` 기준으로 013번 부여)
- 자유 텍스트("13:00") 대신, 시(0~23)/분(00,10,20,30,40,50 — 10분 단위) 휠(스크롤 선택)을
  나란히 배치
- 페이지(모달) 진입 시 현재 시각 기준 다음 정각 또는 30분 단위로 기본값 설정
  (예: 14:37 → 15:00)
- 값이 바뀔 때마다 기존 `toDeadlineIso.ts`(자정 롤오버 포함)를 재사용해 ISO로 변환
- "마감 없음"으로 되돌릴 수 있는 옵션 유지 (007에서 이미 선택 입력으로 확정된 부분)

## 설계 판단

### 1. 기존 흐름과의 통합 지점

`AddMissionModal` → `useAddMission` → `buildAddMissionPayload`(`deadline` "HH:mm" 문자열을
받아 `toDeadlineIso`로 변환) → POST body 순서는 그대로 유지함. `buildAddMissionPayload.ts`/
`toDeadlineIso.ts`는 `model/`에 있어 scope(`ui/**`) 밖이라 수정하지 않았고, 그대로 재사용만
함. 휠 피커는 내부적으로 `{hour, minute}` 상태를 들고 있다가 제출 시점에만 "HH:mm" 문자열로
합쳐서 기존 훅에 넘김 — 기존 계약(문자열 하나)을 바꾸지 않아 `model/` 레이어를 건드릴 필요가
없었음.

### 2. "값이 바뀔 때마다 toDeadlineIso 재사용"의 해석

제출 시점 변환은 이미 `buildAddMissionPayload`가 하고 있어 그 자체로는 "재사용"이 늘 참이
됨. 자정 롤오버가 실제로 어떻게 동작하는지 사용자가 입력 중에 바로 확인할 수 있도록,
휠 값이 바뀔 때마다 모달 안에서도 `toDeadlineIso`를 호출해 "오늘 HH:mm 마감" / "내일 HH:mm
마감" 미리보기 텍스트를 즉시 계산해 보여주도록 했음(`AddMissionModal.tsx`의
`formatDeadlinePreview`). 스펙 문구를 "제출 시 한 번"이 아니라 "휠이 바뀔 때마다"로 읽은
것이고, 자정 롤오버 DoD 항목을 화면에서 바로 확인 가능하게 만드는 목적도 겸함.

### 3. 기본값 계산을 별도 순수 함수로 분리

"다음 정각 또는 30분 단위" 계산(`computeDefaultDeadlineTime.ts`)을 `AddMissionModal.tsx`
안에 인라인으로 넣지 않고 `ui/` 아래 별도 파일로 뺐음 — AGENTS.md의 "새 로직에는 단위
테스트를 추가한다" 규칙을 지키기 위해서였고(자정을 넘기는 경계값 등 검증할 케이스가
있음), scope가 `ui/**`라 `model/`에 넣을 수 없어 `ui/` 안에 순수 함수+테스트로 둠.

### 4. "마감 없음" 옵션 유지 방식

기존엔 텍스트 인풋이 빈 문자열이면 곧 "마감 없음"이었음(007에서 확정된 동작). 휠 피커는
항상 어떤 시/분 값을 들고 있어야 하므로, 별도로 `deadlineEnabled` boolean을 두고 "마감
설정" 버튼으로 켜고 끄도록 함 — 꺼져 있으면 휠 자체를 렌더링하지 않고 "마감 없음"이 보임.
기본값은 꺼짐(기존 텍스트 인풋이 빈 문자열로 시작하던 것과 동일한 기본 동작 유지).

### 5. 휠(스크롤 선택) 구현 방식

외부 라이브러리 없이(scope가 `ui/**` 뿐이라 새 의존성 추가는 과한 판단이라 봄)
`overflow-y-scroll` + `snap-y snap-mandatory` + `scroll-snap-align: center`로 순수 CSS
스냅 스크롤을 구현하고, `onScroll`을 디바운스해 스크롤이 멈춘 위치를 가장 가까운 항목으로
스냅하며 `onChange`를 호출함(`DeadlineWheelPicker.tsx`의 `WheelColumn`). 항목을 직접
클릭해도 즉시 선택되도록 해서 스크롤이 번거로운 경우의 대안도 남김. `role="listbox"`/
`role="option"`/`aria-selected`로 최소한의 접근성 시맨틱을 부여함.

### 1. "지금~오늘 자정" 범위 필터링 로직

새 파일 `deadlineTimeRange.ts`에 순수 함수 두 개를 만듦:
- `minutesForHour(hour, now)` — `now`보다 이전 시(hour)는 분 목록이 통째로 빈 배열(그
  hour 자체를 고를 수 없게), `now`와 같은 hour는 이미 지난 10분 마크만 제외, 이후 시는
  0~50분 전체 허용. 같은 hour에서 남는 분이 하나도 없으면(예: 지금 16:55) 자정을 넘기지
  않기 위해 그 hour의 마지막 마크(50분)만 남기는 안전장치를 둠
- `selectableHours(now)` — 위 함수로 "고를 수 있는 분이 하나라도 있는 hour"만 남긴 목록.
  자정을 넘는 24시는 애초에 `HOURS` 배열(0~23)에 없어서 구조적으로 나올 수 없음

`AddMissionModal.tsx`가 이 두 함수로 매 렌더마다 시/분 휠에 넘길 값 목록을
계산(`hourOptions`/`minuteOptions`)해서 `DeadlineWheelPicker`에 필터링된 배열만 전달함 —
"아예 안 보이게" 쪽으로 구현("선택 불가 상태로 표시"가 아니라 목록에서 제거).

### 2. `computeDefaultDeadlineTime`을 "자정 롤오버" 대신 "23:50 고정"으로 수정

이전 구현은 자정을 넘기면 `% (24*60)`으로 다음날 00:00로 감싸 돌았는데(=007과 같은 롤오버
결과), 이번 요청은 그 결과가 이 화면에서 나오면 안 된다고 명시함. `LAST_SELECTABLE_MINUTE_OF_DAY
= 23*60+50` 상수를 두고 `Math.min(rounded, LAST_SELECTABLE_MINUTE_OF_DAY)`로 바꿔서, 자정에
가까운 시각(23:45, 23:50 등)에서는 다음날로 넘어가지 않고 23:50에서 멈추도록 함. 기존
테스트의 "23:45 → 다음날 00:00" 케이스를 "23:45 → 23:50(그대로)"로 고치고, "23:50 →
23:50(유지)" 케이스를 추가함.

### 3. 모달 안의 "미리보기" 로직에서 `toDeadlineIso` 참조 제거

이제 이 화면이 만드는 입력은 항상 오늘 안이라 "오늘/내일" 구분이 의미가 없어짐. 지난
변경에서 추가했던 `formatDeadlinePreview`(모달 안에서 `toDeadlineIso`를 불러 "오늘/내일
HH:mm 마감"을 계산하던 함수)를 지우고, `AddMissionModal.tsx`가 `hour`/`minute` state를 그냥
직접 포맷해서 "오늘 HH:mm 마감"만 보여주도록 정리함. 이 파일에서 `toDeadlineIso` import
자체를 없앴음 — 실제 ISO 변환은 여전히 제출 시점에 `model/buildAddMissionPayload.ts`(scope
밖, 미수정)가 `toDeadlineIso`를 그대로 호출해서 처리하고, 이 UI가 항상 `now` 이후~오늘
자정 이전의 값만 만들어 넘기므로 그 함수 내부의 롤오버 분기(`deadline.getTime() <
now.getTime()`)는 이 화면에서 나온 입력으로는 사실상 절대 참이 되지 않음(함수 자체는
수정하지 않았고, 단지 이 UI가 그 분기를 타는 입력을 만들지 않을 뿐).

### 4. 실시간으로 범위가 좁아지는 문제 — "지금" 갱신

모달을 열어둔 채로 시간이 흐르면(예: 30분 넘게 열어둠) 처음 계산했던 기본값이 뒤늦게
"이미 지난 시각"이 될 수 있음. `AddMissionModal.tsx`에 `now` state를 두고 30초마다
`setInterval`로 갱신하면서, 그 시점에 현재 선택값이 `now`보다 과거가 됐으면
`computeDefaultDeadlineTime(now)`로 다시 당겨오도록 함. 모달이 열려 있을 때만 인터벌이
돌게(`if (!open) return`) 해서 닫혀 있는 동안은 불필요하게 돌지 않게 함.

모달이 "닫혀 있다가 다시 열리는" 순간에도 `now`가 오래된 값일 수 있어서(마운트 이후 한참
지나 처음 여는 경우 등) 별도로 처리가 필요했음 — `useEffect` 본문에서 곧바로
`setState`를 부르면 이 프로젝트 lint 규칙(`react-hooks/set-state-in-effect`, 011 로그에서도
같은 규칙에 걸린 적 있음)에 걸려서, 011에서 썼던 것과 같은 "렌더 중 조건부 setState"
패턴(React 공식 문서의 "prop이 바뀌면 상태를 조정하기")으로 바꿔 `open`이 바뀌는 렌더에서
바로 `now`/`deadlineTime`을 최신화하도록 함.

### 5. 시(hour) 변경 시 분(minute) 재조정

시 휠에서 hour를 바꾸면 그 hour에서 유효한 분 목록이 달라질 수 있음(예: 지금 14:23인데
14시를 다시 선택하면 [30,40,50]만 유효, 기존에 선택돼 있던 분이 0이었다면 더 이상 유효하지
않음). `handleChangeHour`가 새 hour의 `minutesForHour` 목록에 기존 분이 없으면 그 목록의
첫 값(가장 빠른 유효 시각)으로 자동 보정하도록 함.
