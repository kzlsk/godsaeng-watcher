  `entities/streak/**`, `app/api/missions/**`, `entities/mission/**`, `widgets/MissionBoard.tsx`

## 설계 판단

### 1. "새벽 2시"의 기준 타임존 — KST(UTC+9) 고정

기존 010/011의 모든 "오늘" 계산은 `toISOString()`/`getUTC*`로 UTC 자정을 하루 경계로 썼다.
그런데 "새벽 2시"는 실제 사용자(한국 취준생)의 체감 시각이어야 의미가 있고, 서버 로컬
타임존(Vercel은 UTC, 로컬 개발 환경은 KST)에 따라 결과가 달라지면 안 되므로,
`getUTCHours()` 같은 서버 로컬/UTC 시간에 의존하지 않고 **KST(UTC+9)를 하드코딩**해서
"현재 UTC 시각 + 9시간을 KST 벽시계 시각으로 간주 → 새벽 2시(컷오프)를 빼고 남은 시각의
날짜 부분"으로 "오늘"을 계산했다(`shared/lib/date/getAppToday.ts`). 이렇게 하면 배포
환경(UTC)과 로컬 개발 환경(KST, `Intl.DateTimeFormat().resolvedOptions().timeZone`로 확인)
어디서 실행해도 항상 같은 결과가 나온다.

### 2. 하위 호환: 기존 "날짜 문자열 기반" 순수 함수들은 그대로 재사용

`calculateStreak`/`buildLast7Days`/`calculateWeeklyScore`/`getWeekStartDateString` 등은
이미 "YYYY-MM-DD 문자열을 `T00:00:00.000Z`로 해석해 UTC 달력 날짜로 다루는" 관례를 쓰고
있었다. `getAppToday()`가 반환하는 문자열도 같은 형식이므로, 이 순수 함수들 내부는 전혀
건드리지 않고 "이 함수들에 넘기는 today/reference를 어떻게 구하느냐"만 `getAppToday()`로
바꾸는 방식으로 통일했다. `getAppDayRange()`(UTC ISO 범위, DB `gte`/`lt` 쿼리용)만 신규로
추가해 "새벽 2시 컷오프가 반영된 UTC 타임스탬프 범위"를 계산한다.

### 3. 스코프 경계 — `entities/checkin/**`, `entities/focus-session/**`는 포함되지 않음

티켓 스펙 2번은 "checkins, focus-sessions, streak에서 각자 구현된 today 계산을
getAppToday()로 교체"라고 했지만, 실제로 그 today 계산이 구현된 파일은:

- checkins: `entities/checkin/model/date.ts`의 `getTodayDateString`/`getDayRange`
- focus-sessions: `entities/focus-session/model/dateRange.ts`의 `getTodayRange`
- streak: `entities/streak/model/date.ts`의 `getTodayDateString`/`getWeekStartDateString`

이며, scope엔 `entities/streak/**`만 포함되고 `entities/checkin/**`/`entities/focus-session/**`는
빠져 있다(둘 다 `app/api/checkins/**`/`app/api/focus-sessions/**`엔 포함되지만, "today
계산" 자체가 정의된 곳은 그 엔티티 모델 파일이다). AGENTS.md 규칙("스코프 밖 파일은 수정하지
않는다")에 따라 두 파일은 건드리지 않고, 대신:

- **streak**: `entities/streak/model/date.ts`가 scope 안이라, 그 파일 내부 구현을
  `getAppToday()` 위임으로 바꿔서 `app/api/streak/route.ts`(scope 밖, 미수정)의 동작까지
  간접적으로 새벽 2시 기준으로 고쳤다.
- **checkins/focus-sessions**: 엔티티 파일을 고칠 수 없으므로, `app/api/checkins/route.ts`/
  `app/api/focus-sessions/route.ts`(둘 다 scope 안)가 그 엔티티의 `getTodayDateString`/
  `getDayRange`/`getTodayRange` import를 끊고 `shared/lib/date/getAppToday`를 직접 쓰도록
  바꿨다. 즉 "실제 동작"은 두 라우트 모두 새벽 2시 기준으로 완전히 바뀌었지만,
  `entities/checkin/model/date.ts`/`entities/focus-session/model/dateRange.ts`의 today류
  함수(`getTodayDateString`, `getDayRange`, `getTodayRange`)는 이제 프로덕션 코드에서
  아무도 호출하지 않는 죽은 코드로 남았다(각 엔티티의 `getWeekRange` 등 다른 함수는 여전히
  쓰임). 아래 "블로커" 참고.

### 4. `done` 미션의 "완료된 날"— `created_at`을 근사치로 사용

missions 테이블엔 완료 시각 컬럼이 없다(스키마: `id, user_id, title, category, deadline,
duration_min, done, urgent, created_at`). `entities/streak`가 스트릭 계산에서 이미
"완료된 미션의 `created_at`을 완료일로 근사"하는 관례를 쓰고 있어서(`app/api/streak/route.ts`
주석 참고), `GET /api/missions`의 "오늘 이전에 완료된 미션 제외" 필터도 같은 근사 방식을
그대로 따랐다(`isDoneBeforeToday`, `app/api/missions/route.ts`). `supabase/migrations/**`가
scope 밖이라 `completed_at` 컬럼을 추가하는 정공법은 쓰지 못했다 — 아래 블로커 참고
(며칠 전 만든 미션을 오늘 완료하면 즉시 사라지는 경계 케이스가 있음).

### 5. `overdueDays`를 optional로 선언 — `shared/lib/demo-store.ts` 스코프 밖 문제 회피

`Mission` 타입에 `overdueDays: number`(필수)를 추가했더니 `shared/lib/demo-store.ts`(scope
밖, `app/api/nag/route.ts`가 쓰는 별도의 인메모리 데모 데이터)의 미션 리터럴 5곳이
타입에러를 냈다. 그 파일을 고치는 건 스코프 밖이라, `overdueDays?: number`(optional)로
바꿔 데모 데이터는 그대로 두고 실제 API(`mapMissionRow.ts`)만 항상 값을 채우도록 했다.
`MissionItem.tsx`의 뱃지 조건도 `overdueDays && overdueDays > 0`으로 optional을 고려해
작성함.

### 6. `mapMissionRow.toMission` 시그니처 변경 — `today` 파라미터 추가

`actualFocusMinutes`(오늘만 합산)와 `overdueDays`(오늘 기준 지연 계산)가 모두 "오늘"을
필요로 해서, `toMission(row, today = getAppToday())`로 바꿨다. 테스트에서는 매번 고정된
`today`를 넘겨 결정론적으로 검증했고, `app/api/missions/route.ts`의 GET/POST 둘 다
같은 값을 쓰도록(GET은 한 번 계산해 필터링과 매핑에 재사용, POST는 기본값에 위임) 정리했다.

쪽은 코드 리뷰(정확히 어떤 함수를 호출하는지)로 확인했다.

### 설계 판단 — `formatKoreanDate`(shared/lib/date.ts)를 이 자리에서 더 이상 쓰지 않음

기존 `formatKoreanDate`(`shared/lib/date.ts`, **이번에도 scope 밖**)는
`date.getMonth()`/`getDate()`/`getDay()`처럼 **로컬 타임존 getter**를 쓴다. 그런데
`getAppToday()`는 "YYYY-MM-DD" 문자열을 반환하므로, 이걸 `new Date(`${str}T00:00:00.000Z`)`로
감싸 `formatKoreanDate`에 넘기면 그 함수 내부의 로컬 getter가 **서버 실행 타임존에 따라
다른 날짜를 읽어버릴 수 있다**(예: UTC보다 뒤처진 타임존에서 실행되면 자정 UTC를 전날
저녁으로 읽음). 이러면 DoD의 "컴퓨터 시간대 설정과 무관"을 충족하지 못한다.
`shared/lib/date.ts`는 scope 밖이라 `formatKoreanDate` 자체를 UTC 기준으로 고칠 수도 없다.

그래서 `formatKoreanDate` import를 제거하고, 같은 포맷("M월 D일 요일")을 UTC getter로
읽는 `formatAppDate(dateStr: string)`를 `widgets/DashboardHeader.tsx`(scope 안) 안에
새로 정의해 대체했다. `getAppToday()`가 반환하는 문자열을 `T00:00:00.000Z`로 해석해 UTC
