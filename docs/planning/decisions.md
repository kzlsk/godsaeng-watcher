# 갓생 감시자 — 기획 및 설계 문서

## 1. 프로젝트 개요

- **목적**: 취준 나태함 해소용 개인 도구이자, MCP 연동·Skill 활용·에이전트 하네스 엔지니어링 과정 자체를 어필하는 포트폴리오
- **차별점**: 결과물(투두 앱)보다 "어떻게 AI를 도구로 다뤄서 만들었는가"의 과정이 핵심 메시지. 설계 문서, 프롬프트 버저닝, 실패 대응 등 엔지니어링 흔적을 남기는 것이 중요
- **레포명**: `godsaeng-watcher`
- **표시 이름**: 갓생 감시자

## 2. 기술 스택 결정

| 영역        | 선택                                              | 근거                                                                                                               |
| ----------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 프론트엔드  | Next.js, TypeScript, TanStack Query               | 기존 숙련 스택 재사용                                                                                              |
| 인증        | Supabase Auth (이메일 + OAuth)                    | 멀티유저 지원, Pixel Diary에서 검증된 플로우 재사용                                                                |
| DB          | Supabase (Postgres)                               | 무료 배포/호스팅 용이, RLS로 유저별 데이터 격리                                                                    |
| 백엔드 로직 | Next.js API Routes (또는 Supabase Edge Functions) | 별도 서버 프레임워크(FastAPI/Spring) 학습은 이번 스코프에서 제외 — spring-boot-board 프로젝트에서 별도로 다루는 중 |
| AI          | OpenAI API 실시간 호출 + 에이전트 하네스          | "오늘의 쓴소리" 생성, 이 프로젝트의 핵심 차별점                                                                    |
| 배포        | Vercel                                            | Next.js 기본 배포 타깃                                                                                             |
| OAuth       | Kakao + Google                                    | Pixel Diary와 동일 구성                                                                                            |

**백엔드 프레임워크 관련 메모**: FastAPI/Spring을 써보고 싶은 마음은 있지만, 이 프로젝트의 메시지는 "AI 활용 엔지니어링"이므로 백엔드는 익숙한 스택으로 빠르게 가고 남는 시간을 3번 항목(하네스 설계)에 투자하는 쪽으로 결정.

날짜 뱃지 + 헤드라인 카피("오늘도 미루면 내일의 내가 운다") | 스트릭 뱃지

─────────────────────────────────────

## 4. 데이터 모델 (초안)

- `users` — Supabase Auth 관리
- `missions` (id, user_id, title, category, deadline, duration_min, done, urgent, created_at)
- `checkins` (user_id, date, applications, problems)
- `nag_settings` (user_id, intensity 0-100, persona)
- `nag_logs` (id, user_id, mission_context, content, generated_at, regenerate_count)
- `focus_sessions` (id, user_id, mission_id nullable, started_at, ended_at, duration_min, completed) — 타이머 세션마다 기록. 주간 점수/남은 집중 시간 카드는 이 테이블을 주 단위로 집계해서 계산
- streak은 `checkins` 기반으로 쿼리 시점에 계산 (별도 저장 없이 view/함수로)

## 5. AI 하네스 엔지니어링 설계

- **입력 구성**: 오늘의 미션 상태 + 체크인 수치 + 현재 스트릭 + 사용자가 설정한 페르소나/강도 → 구조화된 프롬프트로 조립
- **페르소나 시스템**: "현실주의 팩폭러" 등 프리셋 페르소나 + 강도 슬라이더(0~100%)로 톤 조절
- **재생성**: "한 번 더 때려줘" 버튼 → temperature/변주를 준 재호출, 로그에 regenerate_count 기록
- **실패 대응(폴백)**: API 실패/타임아웃 시 규칙 기반 메시지 풀로 대체 — 이 폴백 설계 자체가 "그냥 API 호출"이 아니라 엔지니어링임을 보여주는 포인트
- **비용/관측**: 응답 캐싱(동일 조건 재요청 방지), 호출 로그 남기기

## 6. 마일스톤 (초안)

1. Supabase 스키마 + Auth 세팅, 기본 CRUD API
2. 목업 기준 프론트 UI 구현
3. AI 하네스(쓴소리 생성) 구현
4. 테스트, 배포, 설계 결정 회고를 포함한 포트폴리오 문서화
