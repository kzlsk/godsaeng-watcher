# 갓생 감시자 — PRD (Product Requirements Document)

## 1. 개요

- **제품명**: 갓생 감시자 (레포: `godsaeng-watcher`)
- **한 줄 정의**: 취준생의 하루 행동 데이터를 수집해 AI가 상황 맞춤형 팩폭 피드백을 주는 갓생 강제 트래커
- **목적**
  1. 개인용: 인턴 종료 후 느슨해진 갓생 리듬을 강제로 되돌리는 도구
  2. 포트폴리오용: MCP 연동, Skill 활용, 에이전트 하네스 엔지니어링을 적용한 바이브 코딩 개발 프로세스로 AI 활용 역량을 어필
  3. 검증용: 구현 후 지인·커뮤니티에 배포해 실사용자 피드백 수집

## 2. 타겟 사용자

- 1차: 본인 — 프론트엔드 취준생, 인턴 종료 후 자기관리 강제성이 필요한 상태
- 2차: 지인 및 커뮤니티(취준/개발) 사용자 — 유사하게 갓생 강제 도구가 필요한 취준생·자기관리 습관을 만들고 싶은 사람

## 3. 문제 정의

- 마감이나 외부 강제성이 없으면 지원/코딩테스트 준비 같은 자기주도 과업이 쉽게 밀린다
- 일반 투두 앱은 "완료/미완료"만 보여줄 뿐, 밀렸을 때 심리적 압박이나 구체적 피드백을 주지 않는다
- 단순 반복 알림은 무시하기 쉬움 — 사용자의 실제 행동 데이터에 근거한, 매번 다른 맞춤형 피드백이 필요

## 4. 핵심 기능

### 4.1 인증

- 카카오/구글 OAuth 로그인 (Supabase Auth)
- 로그인하지 않으면 대시보드 접근 불가 (미들웨어 보호)

### 4.2 오늘의 미션 (Todo)

- 제목, 카테고리, 마감시각, 예상 소요시간 입력
- 완료 체크, urgent 태그(마감 임박 시 자동/수동)
- 마감 초과 시 시각적으로 티나게 표시

### 4.3 일일 체크인

- 지원 건수, 코테/과제 문제 수 등 정량 기록
- 체크인 여부가 스트릭 계산의 기준

### 4.4 집중 타이머

- 미션에 연결해 타이머 시작 → 세션 종료 시 `focus_sessions`에 기록
- 주간 총 집중시간 / 주간 점수 카드에 반영

### 4.5 스트릭

- 연속 체크인 일수 추적, 끊기면 시각적으로 확 티나게(경고색, 마스코트 표정 변화 등)
- 스트릭 위험 상태를 미리 경고 (예: "오늘 미션 하나라도 놓치면 N일 기록이 끊깁니다")

### 4.6 AI 쓴소리 (핵심 차별 기능)

- **입력 데이터**: Todo 완료율, 마감 초과 여부/횟수, 오늘·최근 집중 시간, 현재 스트릭, 사용자가 설정한 페르소나/팩폭 강도
- **처리**: 위 행동 데이터를 구조화된 프롬프트로 조립 → OpenAI API 호출 → 상황 맞춤형 피드백 생성
- **출력**: 오늘의 쓴소리 카드에 표시, "한 번 더 때려줘"로 재생성 가능
- **실패 대응**: API 실패 시 규칙 기반 메시지 폴백

### 4.7 잔소리 설정

- 팩폭 강도 슬라이더(0~100%)
- 페르소나 선택 (예: 현실주의 팩폭러 등 프리셋)

## 5. UI/디자인

- v0로 초안 목업 제작 완료 (레이아웃/정보구조 확정)
- 디자인 스타일 레퍼런스를 적용해 비주얼 다듬기 예정 — 톤/컬러/타이포그래피는 레퍼런스 확정 후 별도 정리
- 스트릭 끊김 등 상태 변화 시 시각적 피드백(경고색, 마스코트 표정)을 강하게 드러내는 것이 디자인 원칙

## 6. 비기능 요구사항

- **성능**: 대시보드 초기 로드는 인증 확인 후 빠르게 (Next.js 서버 컴포넌트 활용)
- **보안**: OpenAI API 키는 서버 사이드에서만 사용, Supabase RLS로 유저별 데이터 격리
- **비용**: AI 호출은 캐싱/재생성 횟수 제한 등으로 과금 관리

## 7. 개발 프로세스 (포트폴리오 어필 포인트)

- 에이전트(Claude Code 등) 기반 바이브 코딩으로 설계·구현·테스트·배포 전 과정 진행
- 하네스 엔지니어링 요소를 명시적으로 설계: 프롬프트 버저닝, 실패 폴백, 응답 캐싱, 호출 로그(관측성)
- Skill 활용 (문서화/테스트 등 반복 작업에 적용 예정)
- 개발 과정 자체를 README/회고 형태로 기록해 포트폴리오 문서화

## 8. 성공 지표

- 포트폴리오 관점: 설계 문서·개발 과정 기록의 완성도, AI 하네스 엔지니어링 요소가 실제로 동작하는지
- 실사용 관점: 지인/커뮤니티 배포 후 사용자 피드백 수집, 실제 리텐션(연속 체크인 유지 여부)
